# 股票信息管理功能 Spec

## Why
当前系统中股票名称分散存储在各个表中，缺乏统一的股票信息管理。需要建立一个统一的股票信息表，从巨潮资讯获取股票基础信息，并在各个需要输入或显示股票信息的地方提供动态查询和选择功能。

## What Changes
- 新增股票信息表（stocks），存储股票代码、名称等基础信息
- 新增股票信息同步功能，从巨潮资讯 API 获取股票数据
- 修改股票查询页面，增加"获取股票信息"按钮
- 修改黑名单页面，股票代码输入改为动态查询选择
- 修改事件管理页面，关联标的显示股票名称
- 修改股票追踪页面，股票代码输入改为动态查询选择
- 修改仪表盘页面，最近信号展示按新 schema 显示

## Impact
- Affected specs: 股票信息管理、黑名单管理、事件管理、股票追踪、仪表盘
- Affected code: 
  - 数据库 schema（新增 stocks 表）
  - 后端股票服务、黑名单服务、事件服务、股票追踪服务、仪表盘服务
  - 前端股票查询页面、黑名单页面、事件管理页面、股票追踪页面、仪表盘页面

## ADDED Requirements

### Requirement: 股票信息表
系统应提供股票信息表，存储股票基础信息。

#### Scenario: 股票信息表结构
- **WHEN** 系统初始化数据库
- **THEN** 创建 stocks 表，包含字段：
  - id: UUID 主键
  - code: 股票代码（6位数字）
  - name: 股票名称
  - market: 市场（SZ-深市、SH-沪市）
  - createdAt: 创建时间
  - updatedAt: 更新时间

### Requirement: 股票信息同步
系统应提供从巨潮资讯获取股票信息的功能。

#### Scenario: 同步股票信息
- **WHEN** 用户点击"获取股票信息"按钮
- **THEN** 系统从 `https://www.cninfo.com.cn/new/data/szse_stock.json` 获取股票数据
- **AND** 解析 JSON 数据，提取股票代码、名称、市场信息
- **AND** 批量插入或更新到 stocks 表
- **AND** 返回同步结果（新增数量、更新数量）

### Requirement: 股票动态查询
系统应提供股票动态查询 API。

#### Scenario: 根据关键词查询股票
- **WHEN** 用户输入股票代码或名称关键词
- **THEN** 系统从 stocks 表查询匹配的股票
- **AND** 返回股票列表（代码、名称）

### Requirement: 黑名单股票选择
黑名单页面应支持动态查询选择股票。

#### Scenario: 添加黑名单时选择股票
- **WHEN** 用户在黑名单页面添加股票
- **THEN** 提供股票代码输入框，支持动态查询
- **AND** 显示匹配的股票列表供选择
- **AND** 选择后自动填充股票代码和名称

### Requirement: 事件关联标的显示股票名称
事件管理页面的关联标的应显示股票名称。

#### Scenario: 显示关联标的股票名称
- **WHEN** 事件有关联的股票标的
- **THEN** 从 stocks 表查询股票名称
- **AND** 在关联标的列表中显示股票代码和名称

### Requirement: 股票追踪股票选择
股票追踪页面应支持动态查询选择股票。

#### Scenario: 添加股票追踪时选择股票
- **WHEN** 用户在股票追踪页面添加追踪
- **THEN** 提供股票代码输入框，支持动态查询
- **AND** 显示匹配的股票列表供选择
- **AND** 选择后自动填充股票代码和名称

### Requirement: 仪表盘信号展示
仪表盘页面的最近信号应按新 schema 显示。

#### Scenario: 显示最近信号
- **WHEN** 用户访问仪表盘页面
- **THEN** 显示最近信号列表
- **AND** 显示字段：标的代码、动作、分数、生成时间
- **AND** 从 stocks 表查询股票名称并显示

## MODIFIED Requirements

### Requirement: 股票查询页面
股票查询页面应增加"获取股票信息"按钮。

#### Scenario: 获取股票信息
- **WHEN** 用户点击"获取股票信息"按钮
- **THEN** 调用股票信息同步 API
- **AND** 显示同步进度和结果
- **AND** 刷新股票列表
